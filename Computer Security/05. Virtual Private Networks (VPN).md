# 05. Virtual Private Network (VPN)
- A VPN is virtual in that it carries information within a private network, but that information is transported over a public network.
- A VPN is private in that the traffic is encrypted to keep the data confidential while it is transported across the public network.

## Internet Protocol Security (IPsec)
- IPsec (Internet Protocol Security) is a secure network protocol suite used to encrypt and authenticate data packets.
- It ensures secure communication over untrusted public networks and is widely used to establish robust Virtual Private Networks (VPNs) between individual devices, corporate offices, and cloud environments

Using the IPsec framework, IPsec provides these essential security functions:
1. Confidentiality - IPsec uses encryption algorithms to prevent cybercriminals from reading the packet contents.
2. Integrity - IPsec uses hashing algorithms to ensure that packets have not been altered between source and destination.
3. Origin authentication - IPsec uses the Internet Key Exchange (IKE) protocol to authenticate source and destination. Methods of authentication including using pre-shared keys (passwords), digital certificates, or RSA certificates.
4. Diffie-Hellman - Secure key exchange typically using various groups of the DH algorithm.

## Internet Key Exchange (IKE)
- The Internet Key Exchange (IKE) protocol is a secure, automated key management protocol primarily used to set up authenticated, encrypted communication channels like Virtual Private Networks (VPNs).
- It acts as the "handshake" before data transfer, negotiating encryption algorithms and generating the keys needed to secure network traffic.
- IKE utilizes the Internet Security Association Key Management Protocol (ISAKMP)
- An ISAKMP Security Association (SA) is a foundational agreement between two network endpoints that defines how they will mutually authenticate, encrypt data, and establish cryptographic keys. It serves as a secure, logical communication channel for negotiating subsequent IPSec SAs.

There are two phases in IKE: Phase 1, and Phase 2

### Phase 1
In Phase 1, two IPsec peers perform the initial negotiation of SAs. The basic purpose of Phase 1 is to negotiate ISAKMP policy, authenticate the peers, and set up a secure tunnel between the peers. This tunnel will then be used in Phase 2 to negotiate the IPsec policy.

### Phase 2
In Phase 2, the tunnel is then used to safely negotiate Phase 2 (IPsec SAs), which handles the actual encryption and encapsulation of your user data packets.
