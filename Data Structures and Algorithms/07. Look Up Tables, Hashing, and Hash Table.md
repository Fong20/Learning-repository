# 07. Lookup Tables (LUT), Hashing and Hash Table

## Lookup Table (LUT)
- A data structure used to replace runtime computation with a simpler array indexing
- Stores precomputed results for a function or operation, for fast retrieval based on input values
- Commonly used in embedded systems, graphics, cryptography, and digital signal processing
- Improves performance by trading space for time, especially when input range is small and predictable.
- Can be implemented using arrays, hash tables, or associative arrays depending on the application
- Especially useful in real-time systems where speed is critical and computation must be minimized.

## Hash Table
- Use numbers as keys (Array Index)
- Use linked list to store additional data

### Components of Hash Table
1. Key = The unique identifier used to access the data. It acts as an input to the hashing process and can be a string, integer, or any custom object.
2. Value = The actual data or object associated with a specific key.
3. Hash Function = The "brain" of the hash table. It is an algorithm that takes a key as input and computes a numeric index (or hash code). This index tells the table exactly which bucket to store or look up the value in.

### Advantages and Disadvantages of Hash Table

#### Advantages
- Hash tables are significantly faster than trees (O(1))
- Hash tables are relatively easy to program

#### Disadvantages
- They’re based on arrays, and arrays are difficult to expand after they’ve been created.
- For some kinds of hash tables, performance may degrade catastrophically when a table becomes too full
- There’s no convenient way to visit the items in a hash table in any kind of order (such as from smallest tolargest).
- This data structure, is not efficient in operations that require any ordering information among the elements, such as findMin , findMax and printing the entire table in sorted order.


### General process of creating Hash Table
1. You provide a key and its corresponding value to the hash table.
2. The hash function processes the key and generates a hash value.This hash value is adjusted (usually via the modulus operator, %) to fit the size of the underlying array.
3. The value is stored exactly at that generated index.
4. During a lookup, the key is passed through the exact same function to retrieve the value without searching the rest of the table.

### Hash Function
- The "brain" of the hash table. It is an algorithm that takes a key as input and computes a numeric index (or hash code). This index tells the table exactly which bucket to store or look up the value in
- Using the modulo operator (%), we take the returned array elements and modulus the size of the table to find the key (array index).
- At the end, a hash table will be produced.

**Example:**

arraySize = numberWords * 2

arrayIndex = hugeNumber % arraySize

### Collision in Hash Table
- Since the hash table has a fixed array size, different keys may occasionally generate the exact same index. This is called a collision.
- There are two main ways to solve collision, which are open addressing, and separate chaining.

### Open addressing
- When a collision occurs, the algorithm searches linearly or quadratically for the next available empty slot in the array.
- E.g. If cats hashes to 5,421, but this location is already occupied by parsnip , then we might try to insert cats in 5,422.
- Types of Open Addressing include Linear Probing, Quadratic Probing. and Double Hashing
