# 04. Trees
- A tree is an abstract model of a hierarchical structure.
- It composes of nodes and edges
- Num of nodes = Num of edges + 1

## Components of a tree
1. Root node = the topmost, foundational element in a hierarchical tree structure, serving as the starting point for all data traversal, branching, and operations. It is unique because it is the only node in the tree that has no parent and from which all other descendant nodes emerge
2. Leaf node = nodes without any child nodes

## Types of Trees

### Binary Tree
- Trees which have nodes with no more than 2 children.
- If a node has two children, one child is designated as a left child and the other as a right child.

A binary tree can either be a full binary tree, or a complete binary tree
- Full Binary Tree: every node in the tree except the leaves has exactly two children
- Complete Binary Tree: every level of the tree is completely filled except the last level.

#### Tree Traversals
- There are three main ways to traverse (visit) through each node in a binary tree
- Operations such as In-order, Pre-order, or Post-order traversals must visit every single node exactly once to print or process the data. Because the work scales linearly with the number of nodes, it is always O(n) regardless of the shape of the tree.

#### Pre-order traversal
- Print the data at the root
- Recursively print out all data in the left subtree
- Recursively print out all data in the right subtree
- Root → Left → Right

#### In-order traversal
- Recursively print out all data in the left subtree
- Print the data at the root
- Recursively print out all data in the right subtree
- Left → Root → Right

#### Post-order traversal
- Recursively print out all data in the left subtree
- Recursively print out all data in the right subtree

### Binary Search Tree (BST)
A Binary Search Tree (BST) is a node-based binary tree data structure that maintains elements in a strictly sorted order to allow for fast data retrieval, insertion, and deletion

#### Properties of BST
- Left Subtree: Every node in the left subtree has a value less than the parent node's value.
- Right Subtree: Every node in the right subtree has a value greater than the parent node's value.
- Recursive Rule: Both the left and right subtrees must also independently be valid Binary Search Trees.
- insertion, deletion can be performed in BST
- BST has a time complexity of O(log n) if the tree is balanced, but it has a time complexity of O(n) for unbalanced trees

#### Searching for a target value in BST
- Compare the value with the element in the root node.
- If the value is equal , the search is successful
- If value is less , search the left
- If value is greater , search the right
- If the subtree is empty , the search is unsuccessful.

#### Inserting a node in BST
- Initialize the current node with root node
- Compare the key with the current node.
- Move left if the key is less than or equal to the current node value.
- Move right if the key is greater than current node value.
- Repeat steps 2 and 3 until you reach a leaf node.
- Attach the new key as a left or right child based on the comparison with the leaf node’s value.

### Tree Rotations
- A tree rotation is an operation that changes the structure of a binary tree without altering the sequence of its elements. It is the fundamental mechanism used in self-balancing binary search trees (like AVL and Red-Black trees) to decrease tree height and improve operational efficiency

#### Types of Rotation
1. Left Rotation
- Used when a node or its subtree becomes too "right-heavy".
- The right child of the current node is moved up to take its place. The original parent node is shifted down to become the new left child.
- Shifts nodes from the right subtree to the left, decreasing the overall height of the right side

2. Right Rotation
- Used when a node or its subtree becomes too "left-heavy".
- The left child of the current node is moved up to take its place. The original parent node is shifted down to become the new right child.
- Shifts nodes from the left subtree to the right, decreasing the overall height of the left side

#### AVL Trees
- AVL is a self-balancing BST
- In AVL trees, the main property states that The difference between heights of left and right subtrees (balance factor) cannot be more than one for all nodes.”
- Searching, insertion, and deletion are exactly the same as BST.

**Step 1: Identify the height of the nodes**
- Height(node) = 1 + max(height(left), height(right))
- The height of the null node is 0 or leaf node is 1.

**Step 2: Calculate Balance factor of the node**
- The Balance Factor (BF) for a node (X) is the difference in height between its right and left subtrees or difference in height between its left and right subtrees
- The BF is checked after every insertion & deletion, do necessary rotations if out of balance

BF(X) = height(rightSubtree(X)) − height(leftSubtree(X))

**AVL Tree Example:**
- in this example, the height of null node is 0, and the leaf node is 1. The Balance Factor (BF) for a node (X) is the difference in height between its right and left subtrees

#### Red-Black Tree
In a red-black tree,

**Properties of Red-Black Trees**
1. Node Color: Each node is either red or black.
2. Root Property: The root of the tree is always black.
3. Red Node Property: Red nodes cannot have red children (Red nodes cannot be adjacent).
4. Black Node Property: Every path from a node to its descendant leaves must have the same number of black nodes.
5. Leaf Property: All leaves (NIL nodes) are black.

### M-ary Trees / M-way search trees
- A multi-way tree (or m-way tree) is a tree data structure where nodes can have more than two children
- Each node can have from 0 to M sub trees, where M is defined as the order of the tree, which states the maximum number of children any node can have.
- Eg: a node with two data items always has three children, a node with three data items always has four children, and so on.
- each node holds up to M-1 keys and can have up to m child pointers

M-way search tree has the same structure as the binary search tree:
Subtrees to the left of an entry contain data with keys that are less than the key of the entry, and
Subtrees to the right of an entry contain data with keys that are greater than or equal to the
entry’s key

### B-Trees
- A B-tree is a specialized, self-balancing search tree data structure that allows for searching, sequential access, insertions, and deletions in O(log n) time
- Storing multiple keys per node reduces the height of the tree, allowing systems to search, insert, and delete data in secondary storage with minimal disk reads.
- All keys (data values) within a single node are stored in strictly increasing order.
- It is perfectly balanced: every leaf node is at the same depth.
- If a node has k keys, it can have up to k + 1 children.
- A B-tree is defined by a maximum degree / order (often called M). It is essentially the maximum number of children any node can have
- Every node, except the root, must be at least half of the maximum number of keys and can hold at most M - 1 keys. This means only the root node can have minimum of 1 key while other nodes need to have at least 2 keys
- Every internal node except the root must have at least ⌈M/2⌉ children, which means every internal node must have at least M/2 children (and no more than the maximum number of children, M). If a node drops below this minimum during a deletion, the tree must balance itself by merging or borrowing from neighboring nodes

#### Example: 2-3 Trees
- a 2-3 tree is a balanced search tree where every internal node has either two children (a "2-node") and one data value, or three children (a "3-node") and two data values.
- It is also known as a B-tree of order 3. Hence, the maximum number of keys any node can have is 2 (M - 1 = 3 - 1 = 2)
- Because all leaves are kept at the exact same level, the tree is perfectly height-balanced

- A 2-3-4 tree aka 2-4 tree is also known as B-tree of order 4. Hence, the maximum number of keys any node can have is 3 (M - 1 = 4 - 1 = 3)
- Because all leaves are kept at the exact same level, the tree is perfectly height-balanced

#### Searching in B-Tree
The searching operation is similar to a BST.

Follow the below method for searching an element:
1. Start searching from the root of the tree.
2. If the value is present in that node, then the element is found.
3. Otherwise, find the suitable pointer in which the value is based on the node structure.
4. Move to that child and continue from step 1.
5. If a leaf node is reached and the value is still not found then that value does not exist in the tree.

#### Insertion in B-Tree
1. Search for the Leaf Node
- Start at the root node.
- Compare the new key against the keys in the current node.
- Traverse down the appropriate child pointer based on the comparison.
- Repeat this step until reaching a leaf node.

2. Insert into the Leaf Node
Case A: Node has space (Keys < m - 1)
- Insert the new key directly into the leaf node in its correct sorted position.
- The operation is complete.

Case B: Node is full (Keys = m - 1)
- Temporarily place the key in its sorted position, creating an overflow (m keys).
- Perform a node split.

3. Handling Node Splits (Overflow)
- When a node overflows, it must split into two separate nodes to balance the tree
- Find the median (middle) key of the overflowed node.
- Divide the remaining keys into two new nodes: Left child: Keys smaller than the median. Right child: Keys larger than the median.
- Promote the median key up into the parent node.

#### Deletion in B-Tree
The deletion operation is also performed always on the leaf.

The deletion is performed in the following way:
1.Search the node whose value needs to be deleted.
2.If the node is a leaf node then remove the required value from that node and decrease the data elements by 1.
3.If the node is not a leaf node then:
- Find the successor of that node. A successor of a node is the smallest element among the ones which are greater than it or the largest element among the ones that are smaller than it.
- Swap the successor with the current node and delete that node in the leaf.
